# 待会儿吃啥 · 用高德小程序 SDK 把「午饭吃什么」压缩成一次点击

> 高德开放平台开发者案例 · 微信小程序 · 纯前端 · 无后端 · 无本地假数据
>
> 一句话：微信小程序 + 高德地图微信小程序 SDK（`amap-wx`）→ 定位你 500 米内的饭馆 → 把它们贴到转盘上 → 转一次，48 小时内不再纠结吃什么。

---

## 一、问题不是「没得吃」，是「选不出来」

中午 12:03，你站在写字楼大堂，手机里躺着 6 个外卖 App、3 个群聊、2 个同事说「都行」。

真实困境不是缺少选项，而是**选项太多、每个都要评估**：人均多少、走多远、今天想不想吃辣、昨天是不是刚吃过那家。心理学上这叫「决策疲劳」——人在一堆等价选项前的思考成本，远高于对结果的不满成本。

所以这个小程序只做一件事：**把决策权交给一次物理动作（转盘），而不是交给你的大脑。**
你能做的只有两件事：点掉今天不想吃的类别，然后转。

## 二、为什么用高德地图微信小程序 SDK

| 这个产品需要 | 高德提供的能力 | 用到的接口 |
| --- | --- | --- |
| 知道你在哪 | 微信 `wx.getLocation`（GCJ-02）与高德同坐标系，**不需要任何坐标转换** | `wx.getLocation` |
| 只找 500 米内 | 周边搜索（`place/around`），返回结果自带 `distance` 字段（米） | `getPoiAround` |
| 认得出「火锅」「面」「日料」 | POI 的 `type` 是三级类目串，如 `餐饮服务;中餐厅;综合酒楼`，可直接做关键词匹配 | `getPoiAround` |
| 让用户确认坐标没跑偏 | 逆地理编码，把坐标翻译成「广州市越秀区」 | `getRegeo` |
| 不搭服务器、不存用户位置 | 全部请求由小程序直连高德 Web 服务，SDK 只负责拼参数和解析 | — |

选 SDK 而不是自己写 `wx.request` 的原因很实际：SDK 已经处理了 `platform=WXJS`、`sdkversion`、`logversion` 这些高德要求小程序端必须带的参数，**少一个就可能被判成非小程序请求**（实测把 Web 服务的 Key 拿来用会直接 `infocode=10001`，见第五节）。

工程里 `utils/amap-wx.js` 就是高德官方发布的 SDK 文件（约 11 KB，未做任何修改），`utils/map.js` 是一层薄封装。

## 三、一次「转」背后的 5 步链路

用户看到的是「转 3 秒」，实际是下面这条链路。括号里是实测数字（广州北京路，500 米半径）。

| # | 步骤 | 做什么 | 实测 |
| --- | --- | --- | --- |
| 1 | 定位 | `wx.getLocation({type:'gcj02', isHighAccuracy:true})`，强开 GPS，最多等 4 秒 | 精度约 35 米 |
| 2 | 周边搜索 | `getPoiAround({querykeywords:'美食', location:'113.264385,23.129112'})` | 返回 20 家餐饮 POI |
| 3 | 归一化 | 把高德字段拍平成页面认的 9 个字段（见第四节） | 20 条 → 20 条 |
| 4 | 过滤 | 剔除用户点掉的类别 + **按 distance 卡死 500 米** + 按 id 去重 | 全部 ≤ 500 米，最近 182 米 |
| 5 | 补搜 | 过滤后不足 4 家时，用剩下的 10 个类别关键词各补搜一次（每次 10 条），合并去重 | 商圈里通常用不上，郊区很关键 |

### 关键代码：一次周边搜索

```js
// utils/map.js —— 省略错误处理，完整版见文件
const opts = {
  location: '113.264385,23.129112',  // 经度在前、纬度在后，6 位小数
  radius: '500',
  querykeywords: '美食',              // 高德参数名是 keywords，SDK 里叫 querykeywords
  offset: 25,                        // 单页上限 25
  page: 1,
  sortrule: 'distance',
  extensions: 'base',
  // 不传 types：一级类目「餐饮服务」下漏店明显，关键词搜反而更全
  success: function (res) {
    // 高德 SDK 回的是 { markers, poisData }，原始数组在 poisData 里
    const list = res.poisData || [];
    // …归一化 + 半径二次校验
  },
  fail: function (err) {
    // err.errCode 就是高德的 infocode（10001/10003/10007…）
  }
};

amap.getPoiAround(opts);
```

## 四、把一堆 POI 变成「能转的转盘」

### 4.1 统一成 9 个字段

高德返回的字段名和业务代码不该互相污染，所以中间强制做一次归一化：

| 字段 | 来源（高德） | 说明 |
| --- | --- | --- |
| `id` | `id` | 高德 POI id，用于去重和「避开上次结果」 |
| `name` | `name` | 店名 |
| `catKey` | 由 `type` 推断 | 10 个类别 key 之一，可能为空 |
| `category` | `type` | 原始类目串，用于展示 |
| `address` | `address` → `pname+cityname+adname` → `地址暂缺` | `address` 偶尔是数组，先 `join` |
| `latitude` / `longitude` | `location`（`"lng,lat"`） | 解析成数字 |
| `distance` | `distance`（米，字符串） | 缺失时用 haversine 自己算 |
| `emoji` | 由 `catKey` 决定 | 转盘上的贴纸图标 |

### 4.2 类别只做「排除法」，不做「多选题」

10 个类别（小吃 / 快餐 / 面食 / 米饭 / 火锅 / 烧烤 / 日料 / 西餐 / 甜品 / 咖啡奶茶）不是为了让你选，而是为了让你**点掉**——排除比选择便宜得多。

匹配分三步，越往后越宽松：

1. **只看 `type`**：`餐饮服务;外国餐厅;牛扒店(扒房)` → 西餐（最权威）；
2. **`type` + 店名**：`餐饮服务;中餐厅;中餐厅` + `桂林米粉(越华大院店)` → 面食；
3. **泛类目兜底**：`餐饮服务;中餐厅;综合酒楼` 认不出菜系 → 算作米饭，保证「今天不想吃米饭」对普通中餐馆也生效。

第 2 步能生效有个前提：**「米饭」的 token 表里不能放 `中餐厅` 这种泛词**，否则所有中餐馆会在第 1 步就被判成米饭，店名再也不会被看。这条是实测出来的：修之前 `桂林米粉(越华大院店)` 被判成米饭，用户一点「不想吃米饭」就把米粉店一起干掉了。

### 4.3 半径必须自己再卡一次

高德接口自带 `radius`，但这个 SDK 版本**不会把它转发出去**（详见第五节第 2 条），接口会按默认 3 公里返回。所以 `searchNearby` 在拿到结果后，会用每个 POI 的 `distance` 再筛一遍：

```js
const kept = [];
for (let i = 0; i < raw.length; i++) {
  const d = distanceOf(raw[i], origin);        // distance 缺失则 haversine
  if (d === null || d <= radius) kept.push(raw[i]);
}
```

这样「500 米内」才是真的 500 米，而不是接口的 3 公里。

### 4.4 最后一步：抽签

- 池子 < 2 家 → 返回空数组，页面走空状态（不硬凑）；
- 池子 ≥ 2 家 → Fisher-Yates 洗牌后取最多 8 家贴在转盘上；
- 如果这 8 家里有「上次刚转过的那家」，换一家进来（池子太小就不强求）。

## 五、踩坑清单（全部是实测，不是抄文档）

1. **`location` 必须「经度,纬度」**。写成纬度在前不会报错，只会把你搜到另一个城市。
2. **这个 SDK 只转发 `querytypes` 和 `querykeywords`**。`radius`、`offset`、`page`、`sortrule`、`extensions` 全部被静默丢弃——抓包能看到实际参数只有 `key,location,s,platform,appname,sdkversion,logversion,keywords`。所以代码里照样传（换版本自动生效），但**半径一定在客户端再筛一次**。
3. **成功回调拿到的不是 `res.pois`，是 `{ markers, poisData }`**。照着高德 Web API 文档写 `res.pois` 会一直拿到 `undefined`。
4. **`getRegeo` 源码里写死了 `g.roads[0].name`**：如果某地没有道路数据，`roads` 是空数组，SDK 会在自己的回调里抛异常，你的 `success` 永远不会被调用，Promise 永久 pending。外面套一个 5 秒超时兜底才安全。
5. **逆地理返回的是 `formatted_address`**（下划线），不是 `formattedAddress`；`addressComponent` 里 SDK 还拼错了一个 `provice`。代码里两种写法都读，并且依次退回 `roads[0].name`、附近 POI 名。
6. **别传 `types`**。高德一级类目 `餐饮服务` 在部分商圈的漏店率明显高于关键词搜；用 `querykeywords:'美食'` 再自己归类更稳。
7. **小程序 Key ≠ Web 服务 Key**。实测把 Web 服务的 Key 塞进 SDK：`status=0, infocode=10001, INVALID_USER_KEY`；换成「微信小程序」类型的 Key：`status=1, infocode=10000, OK`。同一个账号下两个 Key 不能混用。
8. **接口 `offset` 默认 20**。SDK 不让你改，所以代码里的 `PAGE_SIZE = 25` 只是上限，实际一页 20 条。

## 六、跑起来

1. 用微信开发者工具「导入项目」选择本目录。
2. 去 [高德开放平台](https://lbs.amap.com) → 控制台 → 应用管理 → 我的应用 → 添加 Key：
   - **服务平台必须选「微信小程序」**；
   - 建议绑定你的小程序 AppID；
   - 不要开数字签名（开了会报 `10007`）。
3. 打开 `utils/map.js`，把占位符换成你的 Key：

   ```js
   const KEY = 'YOUR_AMAP_KEY';   // ← 换成你申请的「微信小程序」Key
   ```

4. 发布前到小程序后台 → 开发管理 → 开发设置 → 服务器域名 → **request 合法域名** 添加：

   ```
   https://restapi.amap.com
   ```

   开发阶段可以先在开发者工具「详情 → 本地设置」勾上「不校验合法域名」。
5. `project.config.json` 里的 `appid` 是 `touristappid`（游客模式），请换成你自己的 AppID——高德的「微信小程序」Key 与 AppID 是绑定的，换 AppID 后如果报 `10007`，回控制台重新绑定即可。

**常见报错对照表**

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `10001 INVALID_USER_KEY` | Key 无效，或用成了 Web 服务 Key | 控制台确认 Key 类型是「微信小程序」 |
| `10007` / 平台不匹配 | Key 与当前 AppID 不匹配，或开了数字签名 | 重新绑定 AppID、关掉数字签名 |
| `10003` | 当日免费额度用完 | 次日再试或充值 |
| `10009` / `10012` | 绑定关系异常 / 频率超限 | 看控制台，慢一点再点 |
| 提示「域名没放行」 | 没加合法域名 | 见上面第 4 步 |
| 提示「还没填高德 Key」 | `KEY` 还是占位符 | 见上面第 3 步 |

## 八、几点说明

- **数据全部来自高德开放平台**，工程内没有任何本地餐厅数据；离线或 Key 失效时页面会给出可操作的中文提示，而不是空转盘。
- **没有后端**：不注册、不登录、不收集手机号；历史记录只写 `wx.setStorage`，卸载即消失。
- **没有 UGC**：不出评价、不上传照片，避免内容审核成本。
- 坐标系全程 GCJ-02，不对坐标做任何转换，因此定位与 POI 落在同一套坐标里，误差只来自 GPS 本身（实测 35 米左右）。
